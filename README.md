# Список

Реализация гибкой структуры данных список на языке си, позволяющей благодаря системе ссылок элементов друг на друга добавлять и удалять новые элементы из любой части списка за O(1)

# Что делает и как пользоваться
Основные функции для прямой работы со списком содержаться в файле List.cpp:
- **return_codes createList(list_t\*\* const list_p_p, size_t list_size)** создает новый список, заданной длинны и кладет указатель на него по указателю list_p_p
- **void         printListInConsole       (const list_t\* const list_p)**  печатает все данные списка
- **return_codes addElemInListAfterThat   (      list_t\* const list_p, size_t idx_prev, int value)**  добавляет элемент со значением value непосредственно после элемента с индексом idx_prev в список list_p, "встраиваясь" между соседними элементами
- **return_codes addElemInListBeforeThat  (      list_t\* const list_p, size_t idx_next, int value)**  добавляет элемент со значением value непосредственно перед элементом с индексом idx_prev в список idx_next, "встраиваясь" между соседними элементами
- **return_codes addElemInTailOfList      (      list_t\* const list_p, int value)** добавляет элемент последним в список
- **return_codes addElemInHeadOfList      (      list_t\* const list_p, int value)**  добавляет элемент в начало списка
- **return_codes deleteElemInList         (      list_t\* const list_p, size_t idx_del)**  удаляет элемент, находящийся физически в памяти по указанному индексу
- **void         visualizeListWithGraphviz(const list_t\* const list_p)** генерирует *.dot файл по данным списка и вызывает стороннюю библиотеку graphviz, преобразующую этот файл в *.svg картинку - визуализацию списка

## Фичность
- **Динамическое выделение памяти сразу под массив элементов** память не выделяется под каждый элемент с помощью calloc, она запрашивается сразу под какое-то количество элементов и автоматически реаллоцируется, увеличивая размер списка в 2 раза, за счет чего достигается высокая скорость добавления новых элементов
- **Удобные функции для работы со списком** благодаря функциям добавления в конец, начало списка пользователю не нужно лезть внутрь самого устройства списка 
- **Красивая подробная визуализация (см примеры вывода)** с помощью сторонней библиотеки список может создать картинку с подробным описанием всех элементов, их связей, выделяя красным цветом неправильные связи, если они есть. При этом элементы располагаются так же, как они лежать в памяти, по возрастанию индексов
- **Векторный формат создаваемой визуализации** позволяет сохранить хорошее качество при приближении картинки, что позволяет подробно и приятно изучить данные списка, что помогает при дебаге
- **Верификатор** проверяющий все связи списка позволяют пользователю сразу узнать об ошибке со стеком. Вызывается в начале и в конце любой функции, изменяющий стек при использовании флага компиляции -DIS_VERIFY_PROTECT, а также позволяет выделять красным некорректные связи в списке при визуализации, что сильно упрощает отладку
- **Использование фиктивного элемента** нулевой элемент в массиве элементов - фиктивный. Его значение - яд, next - индекс начала списка, prev - конца. Благодаря этому работа со списком осуществляется еще быстрее, т.к. в функциях добавления и удаления элементов отсутствуют проверки на то, что новый элемент начало/конец списка 
- **Хэш защита** при изменении программой стэка пересчитывается хэш данных, кладется в структуру стэк, затем пересчитывается общий хэш структуры, включающий в себя этот стэк, что позволяет защититься от взломов, ошибок и любых изменений данных, которые делают не наши функции, память под хэши, их проверка и пересчет выполняется только при включенном IS_HASH_PROTECT
- **Гибкая, удобная, глубокая система проверок** - все проверки настраиваются тремя флагами IS_COMMON_PROTECT IS_CANARY_PROTECT IS_HASH_PROTECT, при включении хотя бы одного из них перед и после работы любой функции вызывается проверка структуры по включенным методам проверки. Если все флаги ноль - стэк максимально быстрый, никаких проверок не происходит, если все флаги включены - постоянно проверяются все функции верификации, проверяющие стэк разными независимыми методами
- **Подробный выровненный printListInConsole (см примеры вывода)** - при включенных проверках каждый шаг в консоль выводится подробный отчет о состоянии стэка, включая канарейки и хэши (если соответственный режим включен), при нахождении ошибки верификаторами выводится еще более подробный отчет, содержащий данные о причине и месте ошибки
